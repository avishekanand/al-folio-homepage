Part I

What is data mining?

From a cholera map in 1854 to malware graphs today — and where it sits next to machine learning.
London, 1854

The first data miner — John Snow

The problem A cholera outbreak tore through Soho — ~600 people dead in days. The accepted theory was “bad air” (miasma). Nobody knew the real cause.
  • Snow, a physician, suspected the water — but had no proof.
  • All he had was a list of addresses of the dead. How do you find a cause in that?
He plotted every death on a map
Each red dot is a cholera death. Snow marked them street by street — and a dense cluster began to emerge in the middle of Soho, while whole blocks nearby stayed clear.
One pump explained it all
The deaths ringed one water pump on Broad Street. Snow had its handle removed — and the outbreak stopped. The cluster was the evidence: data mining before the name existed.

Same idea, a different question

Callimachus catalogued the Library of Alexandria — the Pinakes, arguably the first information-retrieval system: structure the data so any work can be found.

Snow found a pattern in the data; the Pinakes found the needle. Both are data mining — turning a pile of data into something that answers a question. This year’s focus: information access.

Data mining sits at an intersection

It borrows from statistics, databases, machine learning, pattern recognition and AI — the overlap at the heart of Knowledge Discovery in Databases (KDD).
Many phrasings, one idea

What is data mining?

Working definition The primary goal of data mining is to extract useful information from a large volume of data and transform it into an understandable structure for further use.
  • “…searching and analyzing a large batch of raw data to identify patterns and extract useful information.”
  • “…the development of models for data in order to extract information from it.”
  • “…analyzing data from different perspectives and summarizing it into useful information.”
  • And crucially — it is done by humans.

Recap

Where data mining lives

The division of labour

Data management stores and serves the train/test data. Machine learning owns the blue middle — which algorithm, how to train it, and the resulting model.

Data mining owns the orange ends: choosing the input features from domain knowledge, and turning the output into insight. Often the learning here is unsupervised.

A healthcare example

Mining first, then predicting

Data mining phase Analyse a large database of patient records — symptoms, diagnostics, treatments, outcomes — with clustering, association rules, anomaly detection to uncover patterns (e.g. fever + cough + shortness of breath → a specific respiratory illness).
Machine learning phase Use those discovered patterns to train a model. A new patient’s symptoms → the model predicts likely diagnoses and suggests treatments from historical success rates.
Data mining finds the structure; machine learning predicts with it.
Cyber security · malware families

A real example: network / graph data

Connections between hosts form a huge graph. Clustering it reveals behavioural profiles of malware families — no labels needed (Nadeem et al., 2020).
Making the result insightful

Visualise groups with heatmaps

Row = connection · column = time · cell colour = bytes transferred. A cluster becomes a readable behavioural signature.
The whole loop

These are all data-mining skills

The data-mining loop

Take the data as is, but select features using domain knowledge → cluster with clustering methods → make the gained knowledge insightful (e.g. heatmaps).

Feature choice, the right algorithm, and a human-readable result — that end-to-end judgement is the craft.

The three V’s

Why is data mining hard?

Volume

  • Too big to fit / scan naively
  • Need scalable algorithms

Velocity

  • Data arrives fast / streams
  • Need approximate yet accurate estimates

Variety

  • Many types & distributions
  • Must adapt methods to each
These three pressures are exactly why we need hashing, sketching, embeddings and dimensionality reduction.

Part IV

A word of caution

Don’t fool yourself. The rest of this lecture is cautionary tales about results that look great and are wrong.
WWII · Abraham Wald

Survivorship bias

Red dots = damage on planes that returned. Where should you add armour? Not where the dots are — where they aren’t (engines, cockpit): planes hit there never came back. Your data is only the survivors.
The horse that could “count”

The Clever Hans effect

Hans seemed to do arithmetic — but was really reading his trainer’s unconscious cues. Models do this too: right answer, wrong reason.
Too good to be true

Shortcuts in learning — Wikipedia citations

The task Automatically predict which Wikipedia sentences need a citation. A neural network scored 100% on the test set — while humans agreed only <55% of the time.
What should you ask?

100% accuracy on a task humans find genuinely hard is too good to be true — a red flag, not a trophy.

The catch: sentences needing a citation already carried the marker “[ ]”. The model learned “if the bracket is there, predict citation-needed” — a shortcut, not understanding.

The canonical ML parable

Shortcut learning — the “Russian tanks”

100% accurate in training, worse than random on new data. The network had learned: “if the sky is blue, no tank; otherwise, tank.” It classified the weather, not the tanks.
Explainable AI reveals the trick

Shortcuts in image models

A classifier labels this “horse” with high confidence. Saliency maps show why: it fires on the copyright watermark in the corner. If “© …” → predict horse.
Multiple comparisons

You can always find what you’re looking for

Test enough hypotheses and some will “correlate” by pure chance. The multiple-comparisons problem is the cause of many data-mining errors — significance you went fishing for isn’t significance.
Lecture 1 · wrap-up

Summary

Take away

Data mining = extract useful information from a large volume of data and turn it into an understandable structure. It focuses on the input and output ends of the ML pipeline, often unsupervised.

Organised around three verticals — Distances · Matrices · Counting. Grading: labs 30% (2 of them), exam 70%.

It’s called the skill of the 21st century — but tread with caution. Survivorship bias, Clever Hans, shortcut learning and multiple comparisons are waiting to fool you.
